# Course 2 — Play It Safe: Manage Security Risks

## Module 3: Introduction to SIEM Tools

---

### Overview
This module is about turning raw event data into something an analyst can actually act on. It starts with **logs** (the raw record of what's happening across systems), moves into **SIEM tools** (which collect and make sense of those logs), covers the **dashboards** analysts watch, and closes with where SIEM is heading and how it protects organizations.

---

### Logs
A **log** is a record of events that occur within an organization's systems. Every device and application is constantly generating them, and they're the raw material behind almost all detection and investigation work. Three common types:

| Log type | Generated by | What it tracks |
|----------|--------------|----------------|
| **Network** | Network devices — routers, switches, firewalls | Traffic moving across the network |
| **System** | The operating system | Events on a single device — logins, startup/shutdown, errors |
| **Application** | Software applications | Events that happen inside an app |

The problem logs create on their own: there are *far* too many, spread across *far* too many sources, for a human to read directly. That's the gap SIEM fills.

---

### SIEM Tools
A **SIEM (Security Information and Event Management)** tool is a software platform that **collects, analyzes, and correlates** log data from across the IT infrastructure, so an organization can detect and respond to threats in real time, investigate incidents, and meet compliance requirements. It gives analysts a single place to see what's happening instead of logging into dozens of systems.

How a SIEM turns a flood of logs into useful signal:
1. **Collect & aggregate** — pull log data in from many different sources into one place.
2. **Normalize** — convert all that data into a single consistent format so it can be compared.
3. **Analyze & correlate** — apply rules to connect related events and flag suspicious patterns.
4. **Alert & display** — raise alerts on what matters and surface it on dashboards.

---

### SIEM Dashboards
A **dashboard** is a visual, at-a-glance display of the most important information — charts, trends, alerts, and metrics — so analysts can monitor activity and spot anomalies without digging through raw logs. Dashboards commonly track **metrics**: key technical attributes like **response time, availability, and failure rate** used to gauge how systems and applications are performing, alongside security signals like alert counts and failed logins.

---

### SOAR
**SOAR (Security Orchestration, Automation, and Response)** is a collection of applications, tools, and workflows that use **automation** to respond to security events. The distinction from SIEM is the key point:

- **SIEM** *detects* and *alerts* — it tells you something happened.
- **SOAR** *responds* — it automates and orchestrates the actions taken after that alert, often by running a **playbook** automatically.

SOAR builds on top of SIEM output to cut down the manual work of responding.

---

### Common SIEM Tools

| Tool | Hosting | What it does |
|------|---------|--------------|
| **Splunk Enterprise** | Self-hosted | Retain, analyze, and search an organization's log data; real-time security info and alerts |
| **Splunk Cloud** | Cloud-hosted | Collect, search, and monitor log data |
| **Chronicle** | Cloud-native (Google) | Retain, analyze, and search data, built for scale |

**Self-hosted vs. cloud-hosted:** a *self-hosted* tool runs on infrastructure the organization owns and manages — more control, more maintenance. A *cloud-hosted* (or cloud-native) tool runs on the vendor's infrastructure — less to maintain and easier to scale. The industry is steadily shifting toward cloud.

---

### The Future of SIEM Tools
Where SIEM is heading:
- **Cloud-hosted / cloud-native** adoption as organizations move their infrastructure to the cloud.
- **More automation**, through tighter SOAR integration, to speed up response.
- **AI and machine learning** to improve threat detection and reduce the manual load on analysts.
- **More connected data sources** (IoT and beyond) feeding the SIEM.
- A shift from reactive monitoring toward a more **proactive** security posture.

---

### How SIEM Tools Help Protect Organizations
- **Centralized visibility** — one place to see activity across every system, instead of siloed logs.
- **Real-time monitoring and alerting** — faster detection means less time for an attacker to operate.
- **Faster incident response** — correlated data and dashboards make investigations quicker and give responders the evidence they need.
- **Compliance** — centralized log retention and reporting help meet regulatory requirements.

---

### Glossary — Key Terms
(SIEM, SOAR, logs, dashboards, metrics, and the specific tools are defined in their sections above.)

- **Incident response** — an organization's quick attempt to identify an attack, contain the damage, and correct the effects of a security breach.
- **Playbook** — a manual that provides details about any operational action (e.g., the steps to follow when handling a specific incident).
- **Operating system (OS)** — the interface between computer hardware and the user; a major source of system logs.
